2.Theory Questions
Here is the summary of our Next.js deep dive. You can use these as quick-reference notes to remember the core purpose of each feature.
1. The Fundamentals

* What is Next.js? A full-stack React framework that adds routing, SSR, and optimizations to standard React.
* Why use it over React? It provides SEO out of the box, faster performance through pre-rendering, and a built-in backend (API routes).
* Hydration: The process where React "attaches" JavaScript logic to the static HTML sent by the server to make it interactive.

2. Rendering Strategies

* SSR (Server-Side Rendering): HTML is generated on every request. Best for live, personalized data.
* SSG (Static Site Generation): HTML is generated once at build time. Best for speed and SEO (blogs, docs).
* CSR (Client-Side Rendering): The browser builds the page using JS. Best for private dashboards and heavy interactivity.
* ISR (Incremental Static Regeneration): Updates static pages in the background without a full site rebuild.

3. Routing & API

* File-Based Routing: Folders in the /app or /pages directory automatically become URLs (e.g., app/about/page.js = /about).
* Dynamic Routing: Using [slug] in folder names to create variable URLs like /blog/my-post.
* API Routing: Creating backend endpoints (JSON) within your project using route.js files.
* Middleware: A "gatekeeper" script that runs before a request completes (used for auth/redirects).

4. Data Fetching (Pages Router)

* getStaticProps: Fetches data at build time for SSG.
* getStaticPaths: Tells Next.js which dynamic paths to pre-build for SSG.
* getServerSideProps: Fetches data on every request for SSR.

5. Performance & Optimization

* Image Optimization: The <Image> component automatically resizes and compresses images to modern formats (WebP).
* Code Splitting: Breaking the app into small chunks so users only download the code for the page they are on.
* Lazy Loading: Delaying the loading of heavy components until they are needed (via next/dynamic).
* Environment Config: Using .env files to store secrets (server-only) and public keys (NEXT_PUBLIC_).

6. SEO & Auth

* SEO Advantages: Fast load times and pre-rendered HTML make it easy for Google to index your site.
* Auth Handling: Managed via libraries like Auth.js (NextAuth), Clerk, or Lucia, usually involving secure HTTP-only cookies and Middleware.

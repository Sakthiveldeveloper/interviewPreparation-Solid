2.Theory Questions

   Here is a condensed study guide of our conversation. You can copy this directly into your notes.
   1. The Basics
      * What is TypeScript? A superset of JavaScript that adds static typing. It catches errors during development instead of at runtime.
      * TypeScript vs. JS: TS requires a build step (transpilation) to turn into JS. JS is dynamic; TS is static and disciplined.
      * Why use it? Better error detection, easier refactoring, and "living documentation" for teams.
      * Large Projects: It improves them by providing clear "contracts" (interfaces) and preventing the "spaghetti code" that happens as apps grow.
   2. Essential Types
      * Basic Types: number, string, boolean, null, undefined.
      * Any: Turns off type checking. Avoid this as it hides bugs.
      * Unknown: A safer any. You must check the type (e.g., typeof) before using the value.
      * Void: Used for functions that return nothing.
      * Never: For functions that never finish (like throwing an error or infinite loops).
      * Enum: A set of named constants (e.g., Direction.Up).
      * Tuple: An array with a fixed length and specific types at each index (e.g., [number, string]).
      * Union Type: Allows a variable to be one of several types (e.g., string | number).
   3. Objects & Custom Types
      * Interface: Defines the "shape" of an object. Great for public APIs and classes.
      * Type Alias: A nickname for any type. Better for unions or complex logic.
      * Readonly: Prevents a property or array from being changed after it's created.
      * Partial: A utility that makes every property in an object optional (?).
   4. Advanced Concepts
      * Generics: Placeholders (like <T>) that allow you to write reusable code that works with many types while staying safe.
      * Assertion (as): Telling the compiler "I know more than you do" about a type. Use sparingly.
      * API Response Type: Use a Generic Wrapper like interface ApiResponse<T> { data: T; success: boolean; }.
      * Decorator is a special kind of declaration that can be attached to a class, method, property, or parameter to modify its behavior or add metadata.
   5. Safety & Best Practices
      * How to avoid any? Use unknown, Union types, Generics, or simply take the time to define an Interface.
      * Handling Optional Data:
      * Optional Chaining (?.): Safe property access.
         * Nullish Coalescing (??): Providing a fallback value.
         * Type Guarding: Using if (typeof ...) to prove a type exists.

✅ TypeScript Theory – Q&A (Interview Revision Notes)
   🔹 Core Fundamentals

      1. What is TypeScript?
         TypeScript is a superset of JavaScript that adds static typing, enabling better error checking and improved code quality.
      2. Why use TypeScript?
         Detect errors at compile time
         Better code readability
         Strong tooling (autocomplete, IntelliSense)
         Easier to maintain large applications
      3. What is Static Typing?
         Static typing means defining variable types at compile time, so errors can be caught before execution.
      4. What is Type Inference?
      TypeScript automatically determines the type of a variable based on its value.
      5. What is the difference between TypeScript and JavaScript?
         TypeScript includes types and compiles to JavaScript, while JavaScript runs directly in the browser without type checking.

   🔹 Data Types

      6. What are basic types in TypeScript?

      string
      number
      boolean
      null
      undefined
      any
      unknown
      void

      7. What is the difference between any and unknown?
         any: disables type checking
         unknown: safer, requires type checking before usage
      8. What is void?
         Used for functions that do not return any value.
      9. What is never?
         Represents values that never occur (e.g., function that throws error or infinite loop).
      10. What are Union Types?
            A variable can hold multiple types.
         Example: string | number
      11. What are Literal Types?
            Specific fixed values as types.
         Example: "success" | "error"

   🔹 Objects & Custom Types
      12. What is an Interface?
         Defines the structure of an object. Mostly used for object shapes and APIs.
      13. What is a Type Alias?
         Used to define custom types, including unions and complex structures.
      14. Difference between Interface and Type?
         Interface → extendable, used for objects
         Type → more flexible (supports unions, primitives)
      15. What is Readonly?
         Makes properties immutable (cannot be changed after initialization).
      16. What is Optional Property?
         Defined using ?, meaning the property may or may not exist.
   🔹 Functions & Generics
      17. How do you type a function?
         By defining parameter types and return type.
         Example: (a: number, b: number): number
      18. What are Generics?
         Generics allow creating reusable components that work with any type.
      19. Why use Generics?
         Reusability
         Type safety
         Avoid duplication
   🔹 Advanced Concepts
      20. What are Enums?
         Enums define a set of named constants.
      21. What is a Tuple?
         An array with fixed types and length.
         Example: [string, number]
      22. What is Type Assertion?
         Telling TypeScript to treat a value as a specific type.
         Example: value as string
      23. What are Utility Types?
         Predefined types to transform existing types:
         Partial
         Required
         Readonly
         Pick
         Omit
         Record
   🔹 Modules & Configuration
      24. What is tsconfig.json?
      Configuration file that controls TypeScript compilation settings.
      25. What is Module in TypeScript?
      A file that exports/imports variables, functions, or classes.

Generics vs decorators
   Think of Generics as "type placeholders" 
   and 
   Decorators as "behavior modifiers.
   " While they both help you write reusable code, they solve fundamentally different problems in TypeScript. 

1. Generics: The "Universal Container" 
   Generics allow you to create functions, classes, or interfaces that work with any data type while keeping the code type-safe. You don't want to write one function for numbers and another for strings if the logic is exactly the same. 
function identity<T>(arg: T): T {
  return arg;
}

let output = identity<string>("hello"); // T is string
2. Decorators: The "Extra Layer"
Decorators are a form of metaprogramming. They allow you to "wrap" a class, method, or property to add extra features (like logging, validation, or dependency injection) without changing the original code's structure. 
function Log(target: any, key: string) {
  console.log(`${key} was called`);
}

class User {
  @Log
  save() {
    // save logic
  }
}
Key Differences in Action
Generics are used when you want a component to accept different types but keep track of what those types are.
Decorators are used when you want to add cross-cutting concerns (logic that applies to many parts of your app, like "only admins can access this") to your existing classes.

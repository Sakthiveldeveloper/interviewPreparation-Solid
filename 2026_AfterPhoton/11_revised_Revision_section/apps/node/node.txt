🔥 3. How Node.js Works (Very Important)
    This is the core concept 👇
    🧠 Traditional Backend (Java, Python)
        One request → one thread
        Slow when many users
    ⚡ Node.js (Event Loop Model)
    👉 Node uses:
        Single thread
        Event loop
        Non-blocking I/O
    🧩 Simple Understanding
    Imagine:
    You order food 🍔
    Instead of waiting, you do other work
    👉 That’s Node.js
    🔁 Flow
        Request comes
        If task is fast → execute
        If slow (DB, API):
        Send to background
        Continue other work
        When done → send response
    💡 Keywords (Important for interview)
        Event Loop
        Non-blocking I/O
        Asynchronous programming
        Callback / Promise / async-await

⚡ What is Fastify?

👉 Fastify = Backend framework (like Express) but faster & more optimized

So:

Express → simple, popular
Fastify → high performance, modern
🧠 Simple Definition

👉 Fastify =
A faster alternative to Express for building APIs in Node.js

⚔️ Express vs Fastify (Core Idea)
Feature	Express	Fastify
Speed	Normal	⚡ Very Fast
Schema validation	Manual	Built-in
Logging	Basic	Advanced
Ecosystem	Huge	Growing
Learning curve	Easy	Slightly more
🚀 Why Fastify is Used?
1. ⚡ High Performance

Fastify is designed for speed.

👉 Example:

Express → handles X requests/sec
Fastify → handles more requests/sec

Used in:

High traffic APIs
Microservices
2. 🧠 Built-in Validation (BIG Advantage)

In Express:
👉 You manually validate data

In Fastify:
👉 You define schema → auto validation

Example:
fastify.post('/user', {
  schema: {
    body: {
      type: 'object',
      required: ['name'],
      properties: {
        name: { type: 'string' }
      }
    }
  }
}, (req, reply) => {
  reply.send(req.body);
});

👉 If invalid → Fastify rejects automatically 🔥

3. 🔥 Better Logging

Fastify uses powerful logger internally
👉 Good for production apps

4. 🧩 Plugin-Based Architecture

👉 Everything is modular
👉 Easy to scale large apps

⚙️ Simple Fastify Example
const fastify = require('fastify')();

fastify.get('/', async (request, reply) => {
  return { message: 'Hello Fastify' };
});

fastify.listen({ port: 3000 });
🧠 When Should You Use Fastify?

👉 Use Fastify if:

High performance needed
Building scalable backend
Microservices architecture
Want built-in validation

👉 Use Express if:

Learning phase
Small/medium apps
Need large community support

🌐 1. REST API (MOST IMPORTANT 🔥)
🧠 What is REST API?

👉 REST = way to design backend APIs

Simple:
👉 Rules for building APIs

🔁 Flow
Client → GET /users → Server → Response (JSON)
📦 Example
GET /users
POST /users
PUT /users/:id
DELETE /users/:id
🧠 Key Concepts
Stateless (no memory between requests)
Uses HTTP methods
JSON data
🔥 Why Important?

👉 90% of backend jobs use REST

🎯 Interview Line

REST is an architectural style for designing stateless APIs using HTTP methods.

🔮 2. GraphQL (Modern Alternative)
🧠 What is GraphQL?

👉 Instead of multiple APIs → one flexible API

❌ REST Problem
GET /user → returns everything (too much data)
✅ GraphQL Solution
{
  user {
    name
    email
  }
}

👉 Only required data 🔥

🧠 Key Concepts
Query → get data
Mutation → change data
Resolver → backend logic
🔥 When Used?
Complex frontend apps
Multiple data sources
🎯 Interview Line

GraphQL allows clients to request only the data they need, reducing over-fetching.

👉 Continuous connection between client & server

👉 ORM = talk to DB using JS instead of SQL

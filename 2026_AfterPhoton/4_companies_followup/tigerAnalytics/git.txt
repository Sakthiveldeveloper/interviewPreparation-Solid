Think of Git like this:

```
Git
├── Basics
│   ├── init, clone
│   ├── add, commit
│   ├── status, log
│
├── Branching
│   ├── branch
│   ├── checkout / switch
│   ├── merge
│   ├── rebase
│
├── Remote
│   ├── push
│   ├── pull
│   ├── fetch
│
├── History Control
│   ├── reset
│   ├── revert
│   ├── amend
│
├── Staging Area (IMPORTANT)
│   ├── working dir → staging → repo
│
├── Advanced
│   ├── cherry-pick
│   ├── stash
│   ├── hooks
│   ├── conflict resolution
```

👉 Golden line:

> **Working Directory → Staging Area → Local Repo → Remote Repo**

# 2 📖 Theory Questions (with clear understanding)

### 🔹 Q1: What is Git?

Git is a **distributed version control system** that tracks changes in code and allows multiple developers to collaborate.

---

### 🔹 Q2: What is the difference between Git and GitHub?

* **Git** → tool (runs locally)
* **GitHub** → cloud platform (stores repos, collaboration)

---

### 🔹 Q3: What is staging area?

It’s a **buffer zone** between working directory and commit.

👉 Why important?

* You can control what goes into a commit

---

### 🔹 Q4: Difference between `merge` vs `rebase`?

**Merge**

* Keeps history
* Creates extra commit

**Rebase**

* Rewrites history
* Cleaner commits

👉 Senior-level answer:

> Use **rebase for clean history**, **merge for preserving team context**

---

### 🔹 Q5: What is `HEAD`?

Pointer to current branch/latest commit.

---

### 🔹 Q6: Difference between `git pull` vs `fetch`?

* `fetch` → just downloads
* `pull` → fetch + merge

---

### 🔹 Q7: What is conflict?

When same file/line changed by multiple people.

---

### 🔹 Q8: Difference between `reset` vs `revert`?

| Command | Effect                     |
| ------- | -------------------------- |
| reset   | removes commit (dangerous) |
| revert  | creates new commit (safe)  |

---

# 3 💻 Coding / Command Questions

### 🔹 Q1: Initialize repo

```bash
git init
```

---

### 🔹 Q2: Add & commit

```bash
git add .
git commit -m "Initial commit"
```

---

### 🔹 Q3: Create branch & switch

```bash
git checkout -b feature/login
```

---

### 🔹 Q4: Merge branch

```bash
git checkout main
git merge feature/login
```

---

### 🔹 Q5: Rebase branch

```bash
git checkout feature/login
git rebase main
```

---

### 🔹 Q6: Fix last commit

```bash
git commit --amend
```

---

### 🔹 Q7: Undo changes

```bash

```

---

### 🔹 Q8: Stash work

```bash

```

### 🔹 Q9: View history

```bash

```

# 4 🎯 Scenario Questions (Senior / Lead Level)

These are **VERY IMPORTANT for interviews like Tiger Analytics 🔥**

---

### 🔥 Scenario 1: Conflict during merge

👉 Situation:
Two devs changed same file

**Solution:**

1. `git pull`
2. Fix conflict manually
3. `git add .`
4. `git commit`

---

### 🔥 Scenario 2: Clean messy commit history

👉 Use:

```bash
git rebase -i HEAD~5
```

👉 Why:

* squash commits
* clean PR

---

### 🔥 Scenario 3: Production bug fix

👉 Steps:

1. Create hotfix branch from main
2. Fix issue
3. Merge to main & dev

---

### 🔥 Scenario 4: Wrong commit pushed

👉 Safe way:

```bash
git revert <commit_id>
```

---

### 🔥 Scenario 5: Work not ready but need to switch branch

👉 Use:

```bash
git stash
```

---

### 🔥 Scenario 6: Large team workflow

👉 Best practice:

* feature branch
* PR review
* rebase before merge

# ⚠️ Tricky Interview Questions (VERY IMPORTANT)

---

### ❓1: Why not use rebase in shared branch?

👉 Because it rewrites history → breaks others' code

---

### ❓2: What happens if you do:

```bash
git reset --hard HEAD~1
```

👉 Deletes last commit permanently

---

### ❓3: Difference between:

```bash
git pull --rebase
```

👉 avoids merge commit → cleaner history

---

### ❓4: Can commit exist without branch?

👉 YES — detached HEAD

---

### ❓5: Why staging area exists?

👉 To create **logical commits**

---

### ❓6: What is fast-forward merge?

👉 No new commit, just pointer moves

---

### ❓7: Why Git is fast?

👉 Uses **snapshots**, not file differences
